# perfect_random — генератор псевдослучайных чисел

Каскадный генератор псевдослучайных чисел с пермутацией ролей компонент.
Разработан как отечественное решение для замены `rand()` и `std::mt19937`
в задачах генерации данных, моделирования и статистических расчётов.

## Принцип работы

### Каскадная динамика

Генератор построен на трёх внутренних переменных `(a, b, c)` — целых числах
в диапазоне `[1, 2³¹ − 2]`, где `M = 2³¹ − 1` — простое число Мерсенна.
На каждом шаге каждая переменная преобразуется по своему правилу:

- **`a`** — затухание: `a = (a × 5/9) mod M`. Множитель `5/9` — обратный элемент
  по модулю M, реализующий дробное умножение в целочисленной арифметике.
- **`b`** — рост: `b = (b × 5/3) mod M`. Аналогично, `5/3` через обратный элемент.
- **`c`** — нелинейность и смешивание: `c = (c² + a + b) mod M`. Квадратичный
  член делает последовательность нелинейной — её нельзя раскрыть матричным
  анализом, в отличие от LCG, MRG или Mersenne Twister.

Множители `5/9` и `5/3` не подобраны эмпирически — они заданы математической
моделью каскада, где одна компонента затухает, другая растёт, а третья
связывает их нелинейно.

### Пермутация ролей

Каждые `N` шагов происходит пермутация — циклический сдвиг ролей:
`(a, b, c) → (c, a, b)`. Переменная, которая была затуханием, становится
нелинейностью; та, что была нелинейностью — ростом; та, что росла —
затуханием. После трёх пермутаций роли возвращаются к исходным.

Это **гарантированный цикл по построению**, независимый от модуля. Пермутация
меняет **роли операций**, а не данные — ключевое отличие от всех известных
генераторов, где переставляются биты или слова.

Значение `N` по умолчанию — **49** для базового генератора. Внутри главного
класса `RNG` каждое ядро использует своё значение: `48`, `49` и `50` —
это снижает корреляцию между ядрами.

### Вывод

```
output = (a × b + c) mod M
```

Смешивание всех трёх компонент в выходном значении устраняет смещение,
характерное для линейных генераторов. Результат приводится к диапазону
`[0, 1)` делением на `M`.


## Архитектура RNG

Поверх базового `CascadePRNG` построен многоуровневый генератор `RNG`
с тремя независимыми ядрами, каждое со своим значением `N`:

- **AssociativityCore** (`N = 48`) — первичная генерация случайного значения.
  Хранит состояние для автоматического ризида.
- **MeanCore** (`N = 49`) — нормализация к целевому среднему с добавлением
  случайного шума от собственного CascadePRNG.
- **FantasyCore** (`N = 50`) — адаптивная коррекция: отслеживает коллизии
  между значениями по их 32-битным raw-значениям и корректирует выход
  на основе битовых различий между столкнувшимися значениями.

Дополнительно:

- **Детекция коллизий** — буфер на 49 значений, перегенерация при совпадении
  (до 49 попыток). Коллизии проверяются по сырым 32-битным значениям.
- **Каскадное порождение зёрен** — под-зёрна для ядер не берутся напрямую,
  а порождаются через временный CascadePRNG (64 бита из двух 32-битных выходов).
- **Автоматический ризид** — срабатывает по периоду ОПЖ (см. ниже)
  или при исчерпании попыток. Новое зерно выводится из текущего состояния.


## Привязка к ОПЖ (ожидаемая продолжительность жизни)

Период ризида генератора определяется геометрической моделью, связанной с **ОПЖ — ожидаемой продолжительностью жизни**. В основе лежат три точки трёхмерного пространства, задающие геометрию вращения: `A`, `B` и центр вращения `O`. Из них вычисляется угол между векторами `OA` и `OB`, угловая скорость и период вращения:

$$
\omega = \frac{\angle AOB}{t_{AB}}, \qquad T = \frac{2\pi}{\omega}
$$

Полученный период `T` (в годах) пересчитывается в количество шагов генератора до ризида:

$$
\text{inc\_max} = \frac{T \times 365{,}25 \times 24 \times 3600}{8}
$$

При `period = 73.8` лет это даёт ~$5 \times 10^{13}$ шагов — генератор работает на одном каскаде практически всё время.


### Важный нюанс: привязка к конкретной ОПЖ

Геометрические точки жёстко зафиксированы в коде:

```cpp
A      = (-3,        -0.5,  -2.5)
B      = (-5/3,      -5/6,   25/4)
O_okr  = (-2.64,     -7.91,  1.65)
```

Генератор **привязан к конкретному значению ОПЖ**. Это означает:

- Расчёты, выполненные для одного значения ОПЖ, **воспроизводимы** —
  один и тот же seed и period дают одинаковую последовательность.
- Если ОПЖ **изменяется** (другая продолжительность жизни, другие точки),
  период ризида меняется, и **все ранее полученные расчёты оказываются
  неверны** — последовательность с тем же seed будет иной.
- Перед сменой ОПЖ необходимо либо завершить все расчёты, либо явно
  зафиксировать, для какого значения ОПЖ получены результаты.

Это не баг, а свойство конструкции: ОПЖ задаёт «частоту обновления»
генератора, и каждое изменение ОПЖ начинает новую историю.


## Отличия от известных генераторов

| Генератор | Линейность | Компонент | Пермутация | Множители |
|:---|:---:|:---:|:---|:---|
| LCG (MINSTD) | Линейный | 1 | нет | подобраны |
| MRG | Линейный | 3–5 | нет | подобраны |
| Mersenne Twister | Линейный | 624 | битовая | подобраны |
| xorshift | Линейный | 3 | битовая | подобраны |
| AES-CTR | Нелинейный | блок | байтовая | стандартиз. |
| **perfect_random** | **Нелинейный** | **3** | **ролей** | **из модели** |

Ключевое отличие — пермутация меняет **роли операций**, а не данные.

## Использование

### Один файл, ничего лишнего

```cpp
#include "perfect_random.hpp"

int main() {
    RNG rng(42, 73.8);   // seed=42, ОПЖ=73.8 лет

    for (int i = 0; i < 100; i++) {
        double val = rng.generate();   // [0.0, 1.0)
        std::cout << val << "\n";
    }
}
```

### Параметры

| Параметр | Тип | Описание |
|:---|:---|:---|
| `seed` | `unsigned int` | Начальное зерно (0 → 1) |
| `period` | `double` | ОПЖ — ожидаемая продолжительность жизни в годах (для ризида) |

### Сборка и тестирование

```bash
# Компиляция worker'а для TestU01
g++ -std=c++17 -O3 -o perfect_random_v3 tu01_worker.cpp \
    -I$TESTU01/include -L$TESTU01/lib \
    -ltestu01 -lprobdist -lmylib -lm

# Полный BigCrush (параллельно)
python3 per_big_crush_v5.py --workers 5

# Отдельный тест
./perfect_random_v3 -t 36 -n 1 -v
```
